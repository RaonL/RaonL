# F5 도메인 전문가 에이전트 시스템 (OpenCLO 기반 설계 초안)

이 저장소는 **단순 챗봇 5개**가 아니라, 질문/설정 요청을 받으면 즉시 도메인별로 정확한 답을 주는 **F5 전문가 시스템**을 빠르게 구축하기 위한 스타터입니다.

## 목표
- 도메인 전문가 5개(F1~F5)를 독립 에이전트로 운영
- 공통 오케스트레이터가 질문을 분류하고 적절한 전문가에 라우팅
- 설정 변경 요청(톤, 출력 형식, 보안 레벨, 도구 사용 정책)을 즉시 반영
- 운영 중 품질(정확도/근거/응답속도)을 측정 가능하게 구성

## 권장 구조

```text
.
├── README.md
├── configs
│   ├── experts.yaml
│   └── system.yaml
├── prompts
│   ├── orchestrator.md
│   ├── f1_expert.md
│   ├── f2_expert.md
│   ├── f3_expert.md
│   ├── f4_expert.md
│   └── f5_expert.md
└── docs
    └── build-plan.md
```

## 동작 방식 (핵심)
1. 사용자의 입력을 `intent`, `domain`, `risk_level`로 해석
2. 오케스트레이터가 **전문가 1명(또는 다중 전문가)** 선택
3. 선택된 전문가가 답변 생성
4. 검증기(guardrail)가 형식/정책/민감정보 검증
5. 최종 응답 반환 + 로그 저장

## OpenCLO 구현 시 체크리스트
- [ ] 에이전트(Orchestrator/F1~F5) 생성
- [ ] 시스템 프롬프트 등록 (`prompts/*.md`)
- [ ] 라우팅 규칙 등록 (`configs/experts.yaml`)
- [ ] 세션별 동적 설정(`style`, `verbosity`, `output_format`) 반영
- [ ] 툴 연결(검색, DB, 사내문서) 및 권한 스코프 분리
- [ ] 테스트 질문셋으로 회귀 테스트

## 빠른 시작
1. `docs/build-plan.md`의 4단계 구축 순서 확인
2. `configs/experts.yaml`에서 도메인 정의(F1~F5) 수정
3. `prompts/f*_expert.md`에서 각 전문가 정책 보강
4. OpenCLO 콘솔/SDK에서 에이전트 등록 후 연동 테스트

## 운영 팁
- 처음엔 도메인당 책임 범위를 좁게 잡으세요(과대 라우팅 방지).
- 답변마다 `근거/가정/불확실성`을 명시하게 하면 신뢰도가 올라갑니다.
- 설정 요청(예: "앞으로 표로 답해")은 세션 메모리에 저장해 다음 턴부터 자동 적용하세요.
